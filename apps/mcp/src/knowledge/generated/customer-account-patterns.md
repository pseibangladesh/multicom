## Customer Account Patterns Reference

### Authentication Middleware

`customerAuthMiddleware` requires a **verified Better Auth session** (HttpOnly cookie) and must be applied to all `/v1/me/*` routes.

Key behaviors:
- API keys (`sk_`/`pk_`) are not accepted as a customer identity
- Unverified email → 403 "Please verify your email address first"
- Sets `c.set('auth', { role: 'customer', userId, email })`

```typescript
import { customerAuthMiddleware } from '../middleware/auth';
import { resolveCustomer } from '../lib/customers';

const route = createRoute({
  method: 'get',
  path: '/v1/me/something',
  middleware: [customerAuthMiddleware] as const,
  // ...
});

app.openapi(route, async (c) => {
  const customer = await resolveCustomer(getDb(c.var.db), c.get('auth').userId!);
  return c.json({ customerId: customer.id });
});
```

### Customer Resolution

`resolveCustomer(db, userId)` (`apps/merchant/src/lib/customers.ts`) maps the session's user to a `customers` row:

1. Find by `auth_provider_id = userId` (the Better Auth user id)
2. Otherwise claim the row with the same email (case-insensitive), e.g. one created by a guest checkout
3. Otherwise create a new row (`auth_provider = 'better-auth'`)
4. Link earlier guest orders placed with that email, then recompute `order_count`, `total_spent_cents` (paid orders minus refunds) and `last_order_at` from the orders table

Because an email is only claimed after it is verified, nobody can take over someone else's guest orders by signing up with their address.

### Profile Endpoints

#### GET /v1/me
Returns the authenticated customer's profile.

Response:
```json
{
  "id": "cus_abc123",
  "email": "user@example.com",
  "name": "John Doe",
  "phone": "+1234567890",
  "created_at": "2023-01-01T00:00:00Z",
  "auth_provider_id": "usr_abc123"
}
```

#### PATCH /v1/me
Updates profile fields. Only whitelisted fields are updatable.

Request:
```json
{
  "name": "Updated Name",
  "phone": "+1987654321",
  "marketing_opt_in": true
}
```

### Saved Cart

Manages persisted cart state:

```typescript
// GET /v1/me/saved-cart
app.get('/v1/me/saved-cart', async (c) => {
  const db = getDb(c);
  const auth = c.get('auth');
  const result = await db.query(
    `SELECT cart_data FROM saved_carts WHERE customer_id = ?`,
    [auth.sub]
  );
  return c.json(result[0]?.cart_data || null);
});

// PUT /v1/me/saved-cart
app.put('/v1/me/saved-cart', async (c) => {
  const db = getDb(c);
  const auth = c.get('auth');
  const { cart_data } = await c.req.json();
  await db.run(
    `INSERT OR REPLACE INTO saved_carts (customer_id, cart_data, updated_at) VALUES (?, ?, ?)`,
    [auth.sub, cart_data, now()]
  );
  return c.json({ success: true });
});
```

### Adding New Routes

To add a new customer-scoped route:

1. Apply `customerAuthMiddleware` to the router
2. Access customer via `c.get('auth')`
3. Use `getDb(c)` for database access

```typescript
// Example: New route for customer notifications
const app = new OpenAPIHono<HonoEnv>();
app.use('*', customerAuthMiddleware);

app.get('/v1/me/notifications', async (c) => {
  const db = getDb(c);
  const { sub } = c.get('auth');

  const notifications = await db.query(
    `SELECT * FROM notifications WHERE customer_id = ? ORDER BY created_at DESC`,
    [sub]
  );

  return c.json({ notifications });
});
```

All examples follow the framework's conventions for database access, context usage, and response formatting.
